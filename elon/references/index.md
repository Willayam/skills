# Elon Reference Index

Use this index when the user's request touches multiple Elon themes and you need
to choose which reference to load.

## Source

Primary source: Eric Jorgenson, `The Book of Elon: A Guide to Purpose and
Success`, free PDF:
`https://book-of-elon.s3.us-east-2.amazonaws.com/The+Book+of+Elon+Free+PDF.pdf`.

References use printed book pages as `[Book, p. N]` or `[Book, pp. N-M]`. Use
the notes as distilled operating guidance, not as verbatim quotation.

## Routing

- **Purpose and ambition:** Read `purpose.md` when the user is choosing what to
  work on, wondering whether the work matters, hesitating from fear, or
  optimizing status instead of usefulness.
- **Truth and physics:** Read `first-principles-and-physics.md` when the user is
  stuck inside convention, copying competitors, arguing from analogy, or needs a
  sharper model of what is actually possible.
- **Hardcore execution and teams:** Read `hardcore-work-and-teams.md` when the
  request involves leadership, ownership, hiring, feedback, resilience,
  exceptional talent, or founder-mode work.
- **Organization, Algorithm, urgency:** Read
  `organization-algorithm-urgency.md` when improving code, operations, product
  scope, meetings, approvals, timelines, communication, or automation.
- **Manufacturing and constraints:** Read `manufacturing-and-constraints.md`
  when the work involves making real things, scaling production, bottlenecks,
  factories, supply chains, deployment throughput, or "the machine that builds
  the machine."
- **Company building stories:** Read `company-building.md` for Zip2, PayPal,
  Tesla, SpaceX, risk, sequencing, prototypes, all-in bets, and company-building
  patterns.
- **Humanity and future:** Read `humanity-and-future.md` for sustainable energy,
  AI, abundance, population, regulation, civilizational fragility, Mars, and
  existential risk.
- **Condensed methods:** Read `musk-methods.md` for a quick checklist of
  operating principles.
- **Source map:** Read `source-map.md` when you need the book's section/page
  structure.

## Response Principle

The skill should behave like an operator's notebook, not a biography. Use the
stories only to sharpen a decision in the user's current context.
