# Inquiry

A ledger for The Work. The `katie` skill asks the questions. This skill remembers
what was asked, what shifted, and what is still charged.

## Where things live

Data lives in the life vault, never in this repo.

```
~/Development/life/inquiry/
  beliefs/        one file per belief, NNNN-slug.md, frontmatter is the schema
  index.md        generated by scripts/build_index.py, do not edit by hand
  candidates/     mined but unreviewed, one file per source
  mining/         raw and filtered transcript dumps, gitignored
```

Read `references/schema.md` before touching a belief file. Read
`references/workflow.md` before changing a status.

## Verbs

### capture

The user voices a stressful thought, or asks to add one.

1. Reduce it to Katie's form. Short, first person, present tense, one thought.
   "My co-founder should answer faster." Not a paragraph.
2. Get the instance. What was happening, when, and the words if there is a record.
   One question if the user gave none, then move on.
3. Check `beliefs/` for the same thought under different words. If found, run
   `scripts/add_instance.py <id>` with date, situation, quote, source. That bumps
   `last_seen`, and sets `status: recurring` if the belief was `turned` or `quiet`.
   Never merge two instances into one.
4. Otherwise run `scripts/new_belief.py` with statement, about, charge, and the first
   instance. It picks the next id and writes the file from `assets/belief-template.md`.
5. Rebuild the index. Reply with the id and nothing else unless asked.

In passing, when the user says something like "I always mess this up" mid-task, offer
once, in one line. "Want that on the list?" If no, drop it.

### mine <source>

Pull candidates out of a body of text. Sources that work today: the life vault
(daily notes, areas, people, history), Claude Code session logs, Codex session logs,
ChatGPT and claude.ai exports.

1. For chat logs, run `scripts/extract_user_turns.py` (user turns only, code stripped)
   then `scripts/filter_turns.py` (keeps turns with a stress marker, splits into chunks).
2. Run `references/extractor-prompt.md` over each chunk. Bulk work goes to gpt-5.6-sol
   through `scripts/run_extract.py`, which shells out to `codex exec`. Journals and
   other high-signal prose go to an Opus subagent reading the files in full.
3. Each run writes `candidates/<source>.md`. Every quote in a candidate block is a
   separate instance with its own date and situation. Nothing enters `beliefs/` from mining.

### review

Turn candidates into beliefs, with the user, one batch at a time.

1. Read the candidate files. Merge duplicates across files. Group under proposed roots.
2. Present the top twenty by charge, one line each. Ask which are real. Do not argue for
   a candidate the user rejects.
3. For each accepted one, run `scripts/import_merged.py "<statement>"`. It creates the
   belief with every instance carried over, creates the root first if needed, and skips
   anything already in `beliefs/`. `--list` shows what is available. `--all` imports
   everything, which is only right if the user has said so.
4. Delete handled blocks from `merged.md` so review is resumable.

### work <id>

Facilitate The Work on one belief and record it.

1. Load the belief file and `katie/references/`. Speak as Katie for the session.
   Pick one instance, the most recent unless the user chooses. Name it in the session
   heading. The questions are about that moment, not about the belief in general.
2. If no worksheet exists and the belief is about another person, fill the
   Judge Your Neighbor worksheet first. Status becomes `worksheet`.
3. Ask the four questions one at a time. Wait for a real answer to each.
   Record the answers under a dated `### Session` heading. Status becomes `questioned`.
4. Turnarounds. To the self, to the other, to the opposite. Three specific
   examples each, in the user's words. Status becomes `turned`.
5. Ask what is truer now. Write it into `current_belief`. Re-rate `charge`.
6. Rebuild the index.

One belief per session unless the user asks for more. Never run the questions on the
user's behalf. The answers have to be theirs.

### status

Run `scripts/build_index.py` and show `index.md`. Lead with one belief, the most
charged open one, not the whole list. Then counts by status, then what came back
(`recurring`), then what went quiet.

## Rules

- Never invent a quote. Sources are verbatim or absent.
- Never change `statement` after capture. If the wording was wrong, add a new belief
  and link it with `root` or `related`.
- The list is not a backlog. Do not show it as one. Do not count "remaining".
- Personal material. Do not copy belief text into any file outside the life vault,
  into commit messages, or into external services.
