# Steve Jobs Reference Index

Use this index when the user's request touches multiple Jobs themes and you
need to choose which reference to load.

## Sources

Unlike the Naval and Elon advisors (single-book skills), the Jobs reference set
draws on a portfolio of public primary sources: the 2005 Stanford commencement
address, the 1995 Smithsonian oral history, the 1995 Cringely "Lost Interview,"
the 1985 *Playboy* interview, the 1996 *Wired* "Next Insanely Great Thing"
piece, *Triumph of the Nerds* (PBS 1996), AllThingsD D5 (2007) and D8 (2010),
the Macworld keynote archive, Andy Hertzfeld's folklore.org, Walter Isaacson's
*Steve Jobs*, Brent Schlender's *Becoming Steve Jobs*, Carmine Gallo's
*Presentation Secrets of Steve Jobs*, and Mona Simpson's 2011 eulogy.

References cite sources with bracketed short names, e.g. `[Stanford 2005]`,
`[Lost Interview]`, `[D5 2007]`, `[folklore.org]`, `[Isaacson]`, `[Schlender]`.
Use the notes as distilled operating guidance, not verbatim quotation. For
exact wording, the user must verify the original.

See `source-map.md` for the full catalog with URLs and conventions.

## Routing

- **Product taste and craft:** Read `product-taste-and-craft.md` when the user
  is making decisions about fit and finish, materials, typography, packaging,
  the unboxing experience, or whether something is "good enough." Also when
  rationalizing mediocrity or treating design as decoration applied at the end.
- **Focus and saying no:** Read `focus-and-saying-no.md` when the user is
  staring at too many features, products, or directions; needs to cut scope;
  is fielding pressure to add a "small" thing; or has lost track of what the
  product actually is.
- **Reality distortion and vision:** Read `reality-distortion-and-vision.md`
  when the user accepts a stated constraint without testing it, defaults to
  what is conventional, or needs to push a team past "impossible." Also when
  the user is trying to anticipate what users will want before they can
  articulate it.
- **Teams and hiring:** Read `teams-and-hiring.md` when the user is hiring,
  building or restructuring a team, dealing with a B-player, choosing whether
  to grow headcount, or deciding who owns what (DRI).
- **Storytelling and keynotes:** Read `storytelling-and-keynotes.md` when the
  user is launching, pitching, naming, writing copy, designing a demo, or
  building a brand narrative. Also for keynote/talk preparation.
- **Mortality and meaning:** Read `mortality-and-meaning.md` when the user is
  procrastinating on what they say matters, choosing a path, fearing failure,
  optimizing for someone else's expectations, or asking whether the work is
  worth their time.
- **Product as strategy:** Read `product-as-strategy.md` when the user is
  deciding build-vs-buy, debating vertical integration, choosing a moat,
  thinking about pricing, balancing engineering with humanities/design hires,
  or evaluating commoditization risk.
- **Wilderness years (NeXT and Pixar):** Read `wilderness-years.md` when the
  user has been fired, demoted, sidelined, or is between acts. Also when the
  user is letting hubris drive them or, conversely, when they need a longer
  time horizon for a comeback.
- **Condensed operating methods:** Read `jobs-methods.md` for a quick checklist
  of operating principles cutting across themes — the fastest way to channel
  Jobs without loading multiple references.
- **Source map:** Read `source-map.md` for the public-source catalog and
  citation conventions.

## Response Principle

The skill should behave like an operator's notebook, not a biography. Use the
stories only to sharpen a decision in the user's current context. Jobs was
often cruel and frequently wrong about people; do not romanticize the cruelty.
The useful interpretation is calibrated honesty plus protection of A-players,
not abuse.
